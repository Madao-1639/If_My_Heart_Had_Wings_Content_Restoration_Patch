# 在这苍穹展翅 内容恢复补丁

为 Steam 版[《在这苍穹展翅》（If My Heart Had Wings）](https://store.steampowered.com/app/326480/) 还原被移除的剧情内容与后日谈，同时完整保留 Steam 成就触发点与官方中文本地化，还原文本使用[羽翼汉化组的汉化文本](https://github.com/jszhtian/oozora_CHSpatch)。

本补丁仅供已购买正版游戏的用户使用，不包含任何游戏本体文件。

> > **当前版本：v0.1.0** — 内容还原与汉化已落地，等待全量实机验证。

## 安装方式

从 [Releases](../../releases) 下载 `IMHHW_Content_Restoration_Patch_Installer_vX.X.X.exe`，双击运行。

安装器会依次执行以下步骤：

1. 定位游戏目录（Windows 下按 Steam 库自动检测，未找到时可手动输入路径）
2. 检查增量文件是否齐备
3. 列出将被修改的文件，等待确认
4. 就地合并资源、覆盖脚本与文本，并在安装后逐文件校验

安装器只携带增量部分，合并时需要读取游戏现有文件，因此无需下载完整归档。**不要重复安装。** 安装完成后即可删除安装器。

## 卸载与恢复

补丁**不创建备份**。被修改与新增的归档通过 Steam 恢复：

1. Steam 库中右键游戏 → 属性
2. 已安装文件 → 验证游戏文件完整性

Steam 会检测出被修改的归档并重新下载。

**验证完整性之后还需手动删除补丁新增的文件**，Steam 不会清理目录里多出来的东西：

```
<游戏目录>/
├── PVOICE.arc      ← 删除
├── PCHIP.arc       ← 删除
└── RIO/            ← 删除整个目录（后日谈脚本）
```

这三项只在后日谈运行期被读取，而入口开关与资源路由随 `Script.arc`、`Rio.arc` 一起被 Steam 还原后已经关闭，留着它们不会再改变游戏内容；删除是为了把补丁文件彻底清除。

## 更新补丁

先按[卸载与恢复](#卸载与恢复)回到原始状态，再按[安装方式](#安装方式)安装新版本。

直接覆盖安装也能工作（同名成员会被新版替换），但新版中已撤销的还原资源不会被自动清除，可能留下无用成员；因此不推荐跨版本直接覆盖。

## 会被修改的文件

| 文件 | 处理方式 | 内容 |

| `zh-CN/Rio.arc` | 覆盖 | 中文文本：还原段落的中文、后日谈 4 篇的中文、角色名牌表合并；**官方中文条目原样保留** |

| `GRAPHIC.arc` | 合并 | 还原场景的图层素材 + 后日谈分层立绘 |

## 实现原理

Steam 版删去了原版的一部分剧情场景与后日谈，保留下来的 H 场景出入口也被改写为「没有发生过」的语境。

本补丁的策略是**增量补充 + 就地还原**：

- **Steam 素材保留、和谐画面换回原版** —— 语音、成就调用、官方中文一律不替换；与原版同名的**画面**素材只是为遮挡裸露而改过画，一律**整名换回原版画面**，素材名与位置不变（见[同名冲突素材](#同名冲突素材)）
- **补回被删除的场景** —— 5 个整场景脚本，加上 26 个脚本内部被删掉的段落，连同对应的 CG、立绘、语音、音效与中文文本
- **还原 H 场景出入口的衔接段** —— 出入口脚本同样被改写过，补丁以 Steam 脚本为基底把差分段落还原为原版内容，让剧情衔接自然
- **解锁后日谈** —— 原版后日谈（4 个角色短篇）在 Steam 版被关在入口开关之外，补丁解除门控并按原版方式补入脚本与资源
- **不新增脚本、不新增跳转** —— 只在被删处补回内容，选项分支结构未被改动；唯一的例外是把出入口被改写的 5 处尾跳**恢复成原版目标**

结果（机检口径）：还原内容的入口与出口全部可达，文本槽位与脚本逐格对齐，官方中文与 Steam 语音未被替换，成就调用与编号逐点保留；还原区间之外的内容不被触碰，唯一的例外是判定表登记的同名画面成员——整名换回原版字节，号位被挪用的那张还要改写保留段落里对应那一句的引用名（接入状态见[同名冲突素材](#同名冲突素材)）。实机运行验证见[已知情况](#已知情况)。

## 已知情况

### 实机验证进度

自动化验收（归档完整性、调用链可达、成就触发点逐点不变、资源配对、改动面收敛、交付表一致）已全部通过，但**关键场景的实机测试尚未执行**。

### 还原文本来源

还原段落的中文来自[羽翼汉化组的汉化文本](https://github.com/jszhtian/oozora_CHSpatch)，已逐行映射回原版脚本并完成全量通读校对。Steam 原有文本保持官方译文不变。

还原内容补回的是原版脚本，其中文按台词槽位封进中文文本档，因此**游戏语言需选择中文**；选其他语言时，官方本地化不覆盖还原段落，这些段落会显示脚本内嵌的日文原文。

### 后日谈的进入方式

后日谈是标题菜单上的额外入口（原版「Sweet Love」按钮）。**通关任意一条角色线即可点亮入口**；进入后的选择界面按角色**逐条解锁**——只有已通关角色的短篇可选，其余海报为灰态。

四篇短篇分别是小鸟、扬羽、天音，以及亚纱＆依瑠。进入后会自动改用补丁新增的 `PCHIP.arc`、`PVOICE.arc` 与 `RIO/` 中的脚本。

原版还有一条从「回想」进入后日谈的路径，Steam 版该入口的数据端不完整，本版沿用 Steam 现状，因此**只有标题菜单一条入口**。

### 回想与 CG 鉴赏列表

游戏内可正常观看全部还原场景与后日谈，但鉴赏（回想）列表的条目索引是独立数据，本版未扩展，因此**还原内容的缩略图不会出现在列表中**。这只影响事后回看的入口，不影响初次观看。

列表用的缩略图取自系统归档 `SysGraphic.arc`，属界面层，本版不改动 ⇒ 个别条目的缩略图与正文画面可能不一致。

### 同名冲突素材

Steam 版改动过少数与原版**同名**的画面素材，处理方针是**一律换回原版画面**；唯一的例外是 Steam 保留段落里确实有一句台词在引用「另一张图」，这时只改写那一句的引用名：

- **同一张图被和谐改画**——形态有两种：在原画上补画遮挡以减少裸露（例：温泉场景给人物补上浴巾）、或把原图放大后裁掉裸露区域。这类一律**用原版画面替换**，不再保留 Steam 的和谐版，素材名与位置都不变，因此不影响脚本与成就。覆盖名单（`resource/censor_map.json` 的 `action=overwrite` 子集）已接入写盘链，逐名整名换回原版字节；正文里被删的场景、文本、语音与后日谈不受影响。
- **同一编号在 Steam 里被挪去当另一张图的替身**——Steam 把某个编号的画面换成了另一幕的图，而它保留下来的剧情里恰好有台词在用这个编号。这类**同样整名换回原版画面**，另外把**还原之后仍然保留的那一句**引用的名字改成它真正该显示的那张图的原版名字，保留段落就不会错位；被还原掉的段落不再消费 Steam 素材，不需要额外保护。
- **只有重编码带来的细微差别**（画面内容一致）——不做处理。

不论哪一类，都不动语音、官方中文与成就调用。界面与鉴赏列表用的系统图属另一层，本版不改动。

### 成就系统

补丁保留全部 Steam 成就调用与解锁标记；被还原段落覆盖的 Steam 脚本，其中的成就调用也逐点原样保留，成就编号不做任何改写或重算。补丁**不新增**成就——还原内容本身在 Steam 侧没有对应的成就条目，播放还原场景不会额外解锁成就，也不会让全成就变得无法达成。

## 目录结构

```
├── backup/         Steam 原版基线（只读，用于计算增量）
├── doc/            技术文档（还原范围、路线、引擎与后日谈机制、验收标准）
├── resource/       全部输入表（逐表字段与读写关系见 resource/README.md）
├── tool/           通用库（归档 / 脚本 / 文本编解码）＋ 安装器源码 install.py
├── script/         构建与验收脚本（顶层入口 ＋ build/ 构建、checks/ 校验、corpus/ 语料）
├── asset/          完整产物（构建后生成，不入库）
├── payload/        增量补丁（构建后生成，仅 METADATA.json 入库）
├── releases/       安装器成品（构建后生成，不入库）
└── VERSION         版本号（唯一来源）
```

产物可从 `backup/` + `resource/` + 原版发行目录完整重建，构建与验收流程见 [doc/restoration-route.md](doc/restoration-route.md)。
