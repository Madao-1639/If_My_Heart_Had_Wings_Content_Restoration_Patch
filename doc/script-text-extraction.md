# 脚本文本提取与民汉译文匹配

本文件记录：**提取口径**（哪些文本算一行、如何解析）、**民汉表的性质**（位置式队列及其失效模式）、**术语/字形对齐规则**（机械层规则族与官方口径裁决）、**已入库产物清单**。过程稿（逐轮进展、一次性脚本、批处理明细）一律留 `tmp/`，不入本文件。

## 1. 提取口径

### 1.1 文本来源

- **`Rio.arc`**：主线剧情对话（50,990 条）。
- **磁盘裸 `RIO/`**：11 个 `.ws2`（`CO1_001/002/003/015`、`HUT_004/005`、4 个 `SL_*`、`start`），7,277 条；含特殊场景（H 场景等）与后日谈。
- 合计 58,267 条文本。

### 1.2 对话行格式

```
\x14 <idx:u16> <flag:u16=0> <speaker\0> <Shift-JIS 对白>(%K%P|%K|%P) \0
```

- `idx` = 槽位号（= `lng_idx`）；`speaker` 实测只有 `char`（对白）与空（清屏行，文本恰为 `%P`）两种。
- 解析一律用**结构化行解析**（§1.4），不得用正则硬编码 `char\0`——会漏掉空说话人清屏行。

**CRC32（引擎查表键）**：文本（含 `%K`/`%P` 标记）→ cp932 解码 → UTF-16LE 编码 → CRC32（有符号 int32）。

### 1.3 选择分支菜单选项

选项标签是**裸日文（无 `%K`/`%P` 标记）**，位于 `\x0f <选项数>` 引导的块内：

```
\x0f <选项数> [ <id:u16> <标签>\x00 <3字节> \x07 <目标脚本名>\x00 ] ...
```

- `FLAG_CHECK` 变量表同构：`\x04 FLAG_CHECK\x00 \x0f <项数> [ <id:u16> <标签>\x00 <8字节> ] ...`
- 提取见 `tool/scriptext.py` 的 `script_rows()`（`kind='menu'`／`'flag'`）。

### 1.4 行模型与噪声排除（`tool/scriptext.py`）

一个脚本的"文本行" = 所有会被显示层消费的字符串，按字节偏移排序，五类：

| `kind` | 形态 | 槽位 |
| --- | --- | --- |
| `dlg` | `\x14 <idx:u16> <flag=0> <speaker\0> <text>%K%P\|%K\|%P\x00` | `idx` |
| `ctrl` | 同上但 speaker 为空（清屏行，text 恰为 `%P`） | `idx` |
| `name` | `\x15 %LC<名>\x00` | 无（独立原始行，不占 idx） |
| `menu` | `\x0f` 选项块内 `<id:u16> <标签>\x00 … \x07<目标脚本>\x00` | `id` |
| `flag` | `FLAG_CHECK` 变量表内 `<id:u16> <标签>\x00` | `id` |

**噪声排除**：`\x14` 巧合命中二进制块（flag≠0、speaker 不是 char/空、text 含 NUL、空 speaker 但 text 不是 `%P`）一律丢弃；`FLAG_CHECK` 扫描只认真标签（必 cp932 可解码且含非 ASCII 字符，否则 `CO1_018` 这类脚本的槽位数会虚增到 3 万余）。

接口：`script_rows(name, data)`、`collect_scripts(orig_dir)`、`all_rows(orig_dir)`、`crc32_signed(bytes)`；原版素材目录由 `IFMH_ORIG_DIR` 提供。消费方：`script/corpus/align_corpus.py`、`script/corpus/build_fan_translations.py`、`script/build/build_carrier_map.py`、`script/build/build_l4.py`、`script/build/convert_sl_ws2.py`、`tool/v5lib.py`。

## 2. 民汉表的性质

### 2.1 位置式逐行 dump

民汉表（`AdvPatch.dll` 的 PE 资源 `PAK/#101`）**不是键值映射，而是按原版脚本出场顺序逐行倾泻的位置式队列**：87,342 个 `TextStruct{int32 crc32; wchar_t str[126]}`（步长 256 字节），条目序 = 发行时那份脚本集的行序，键值只是该行的 CRC32。

**运行时查表语义**：dll 用**一个全局游标**做"最近匹配"——同一 CRC32 的候选里按游标位置取下一个；**任何一次未命中都会让游标复位**，其后所有行从表头重新匹配 ⇒ 同一句译文被连续重复输出。这就是玩家反馈的"复读"的机制成因：不是个别条目错值，而是位置游标一旦失步就成片复发。原版与 Steam 脚本行序存在差异、加之表内本身缺行，失步不可避免。

**本项目从构造上消除该失效模式**：产物是按 `idx` 直接索引的逐脚本 JSON（§5），装载侧不做任何模糊/最近匹配 ⇒ 无游标复位。"逐条键值对齐"的旧做法（按 CRC32 找译文）已废弃，改由位置对齐（LIS 锚定 + 局部 Needleman-Wunsch，§3.1），错位窗口被逐条检出并就地纠正。

### 2.2 匹配方向与同名脚本

- 双向覆盖率 ≥ **99.98%**：提取集合（对白 49,920 + 角色名标记 99 + 菜单选项 14 = 50,033 个唯一 CRC32）几乎全部有译文；剩余未匹配为同句异形/子串冗余条目或个别待查，不影响使用。
- **同名脚本（`CO1_*`、`HUT_*`、`start`）非覆盖关系**：5 个脚本两来源完全相同；`HUT_004`/`HUT_005` 各有 1 条差异，且民汉表匹配的是 **`Rio.arc` 版本**（`HUT_005` 的 `検討`→`見当` 勘误属 `RIO/` 独有，不在民汉表）。`RIO/` 的主要作用是提供 `Rio.arc` 中不存在的 `SL_*` 后日谈脚本。
- **控制符以脚本内日文原文为准**（脚本已写明 `%K`/`%K%P`），表中"同句异形"条目是冗余；对话行按 `lng_idx` 映射时只看主行，主行 100% 有译文。

## 3. 缺陷纠正流水线

玩家反馈的五类缺陷（复读、译名不统一、繁简混合、漏翻、译校批注残留）不靠一次性人工编辑，而固化为「对齐 → 两层改写 → 门禁出包 → 复检」的可复跑流水线。输入一律在 `resource/corpus/`：日文底稿 `jp/`、民汉旧提取 `zh/`、行对齐 `pairing.jsonl`、语境改动表 `review_fixes.jsonl`（每行 `from` 记录来源层，本表即语境改动的唯一终态）。

### 3.1 位置对齐（`script/corpus/align_corpus.py`）

底稿 A = 原版脚本抽出的文本行，底稿 B = 民汉表。先在 crc 唯一处求 LIS 作锚，再在锚间做局部 Needleman-Wunsch，得到逐行对应关系 → `resource/corpus/pairing.jsonl`，每行带 `kind`（dlg/name/menu/flag/ctrl）与 `src` 溯源标记。台词顺序由 idx 锁定，对齐只在同脚本内做，绝不跨脚本搬运。

### 3.2 两层改写

| 层 | 载体 | 性质 |
| --- | --- | --- |
| 机械层 | `tool/textfix.normalize()` | 零判断、每次构建全量执行、幂等 |
| 语境层 | `resource/corpus/review_fixes.jsonl` | 逐槽位记录，`from` 标来源层；本表即改动的唯一终态 |

- 语境改动合成规则：并发评审提案按同槽位**多数写法胜出**，人工裁决层按文件名顺序**无条件覆盖**提案；`script/corpus/merge_fixes.py` 按此规则从零重建整表，新一轮改动则按槽位增量并入。**该表不可再由脚本重算**（是语境改动的唯一副本）；源层缺失时 `merge_fixes` 拒写，以免洗空已有槽位。
- **层序**：最后生效的是 `pin_zsweep`（全量逐行通读），其前是 `pin_zsem`（风险区逐行语义终审），`pin_variants` 是它们之前可整表重写的一层；语义层结论由 `z` 前缀压过全部上游层。**定字类裁决（专名、称谓）必须改「生效层」**：只写下游层会被上游沿用旧写法的条目覆盖回去，落地后要用**分布机检**复验「少数写法归零」，而不是检查改动表是否包含该槽位。
- `merge_fixes` 对提案/pin 只拒三类：空串、残留假名、与日文整行相同。假名判定**先剔除 `ー` 与 `・`**（落假名区间但机械层会换成 `—`/`·`，一刀切会误杀含延长音的整行）。
- **只报/只改该行自身**的硬伤：同一假名词在不同行的不同写法、敬称风格、可通的近义意译、跨行统一诉求一律不动——跨行统一等于重写民间汉化的行文。评审判据与交付格式固化在 [sem-review-protocol.md](sem-review-protocol.md)。

### 3.3 机械层规则族（`tool/textfix.py`）

1. **工作批注剥除**：`【润色：…】`、`（注：…）`、行尾 `*注：…`（到引擎标记前）与点名的少数无关键词批注。
2. **引擎注音剥除**：`{正文:读音}` 只留正文；日文假名括注整块删除。
3. **假名残留清理**：孤立促音/拨音与单字假名（半译残留）删除；多字假名串属整句未译，只报不改。**副作用必须复检**：整行只是拟声词时（`ズビシッ！`）剥完只剩 `！！`——非空、无假名，门禁拦不住，须另由语境层按日文改写。
4. **译名统一**：多数形式胜出（蝶羽→扬羽、加奈子→佳奈子、晨风云→阵晨风云…）。
5. **繁简与日式字形**：`LCMapStringW(2052, LCMAP_SIMPLIFIED_CHINESE)` 逐字转换，再补 `GLYPH_MAP`。判定方法是用 **GB2312 编码可行性反查**点名简中收不到的字，再逐字分档（日式新字体进映射表；人名生僻字与中文拟声保留；需整句改写的留给语境层）。⚠️ 简转会留半成品：LCMap 把日式字只转到繁体就停，而该繁体本身在 GB2312 内 ⇒ 编码反查看不见，只能靠 `GLYPH_MAP` 逐字收尾并归零断言。**层序**：`TERM_FIX` 先于 `to_simplified`/`GLYPH_MAP` 执行，同一条中文词表规则对日文写法不生效，须单列。
6. **称谓按性别落地**：`名字+前辈` 依角色性别改写作学姐/学长，带停顿的独立呼语不动。
7. **句读缺陷**：`。。`/`，。`/`，，`/`、、` 折叠，汉字后的半角逗号转全角。
8. **货币单位**：数字后的 `圆`/`日圆`/`日元` 统一为多数写法 `円`（限定左侧是数字，不动其他货币）。
9. **日文排版残留**：全角数字与全角拉丁字母 NFKC 折叠为半角、全角 `％`→`%`（右侧是 `K`/`P` 时不折叠，以免凭空造出引擎标记）、数字之间的句号改回小数点、残留拉丁单位 `m`→`米`。
10. **未翻的日文词**：`寮母`→`管理员`、裸 `寮`→`宿舍`、`部室`→`活动室`。表序必须排在 `オンボロ寮→破旧宿舍` 之后，否则裸 `寮` 会先把该词条拆坏。
11. **日文半角钩括**：`｢｣`→`「」`。
12. **同音错字（限定语境）**：日文叹气/笑声 `ハァ`、`はは` 被写成"蛤"的改回"哈"，负向断言保住"蛤蟆/蛤蜊"；报告动词"…到"改回"…道"，用后接句读的前视断言限定。这类规则放机械层（在所有 pin 层之后统一执行），写进 pin 反而会被上游层的 RAW 派生写法覆盖回去。
13. **未翻的日文词「部活」**：`部活(?!动)`→`社团活动`。必须带负向断言，否则会把"俱乐部活动/滑翔部活动/腰部活动"改成"俱乐部社团活动"；断言挡不住的真·社团义交语境层逐槽处理。
14. **专名形近错字与少数写法**：`佳柰子`→`佳奈子`、`亚沙`→`亚纱`（须紧跟 `亜紗→亚纱` 之后，先于称谓规则）、`杨羽`→`扬羽`、`航海日志`→`航行日志`。凡"跨语料只有少数几站写错"的字形类事故都走这条通道（一次清零 + 复检归零）。
15. **软换行后的半角缩进**：`\n` 之后跟半角空格折叠成全角 `　`。替换体必须写成 `lambda`：字符串形式的 `'\\n　'` 会被 `re` 还原成真实换行。
16. **说话名不走机械层**：`NAME_FIX` 的**值**直接写进 `NameTable`，不经过 `normalize()`（全角折叠、繁简转换对说话名无效，值须就地写成简体半角）；**键**必须保持日文全形（改键等于查不到）——"键用日文形态、值用中文形态"的不对称约束。
17. **出包期三步（不在 `normalize()` 内，由 `emit()` 串起）**：`drop_dangling_break` 只在中文软换行多于日文时删行尾那一个不承载正文的 `\n`（正则尾巴必须写 `(?:%[KP])*$`；句内多出的换行不动）；`align_terminator` 令行尾 `%K`/`%P` 组合与日文严格一致；`balance_brackets` 只在该行自身 `「`/`」` 数量不等时出手（**日文侧本身不配对则原样保留**，镜像日文不做无依据补全）。
18. **句读误敲与半角括号**：`(`→`（`、`)`→`）`；`(?<=[吗呢吧])》`→`？`（民汉把问号敲成书名号后半，都收在语气词之后；其余 `《》` 逐行核对是真的书名/节目名则保留）。

### 3.4 构建门禁（`script/corpus/build_fan_translations.py`）

出包前逐条断言，任一不过即拒绝产物：G1 非空、G2 无假名/无注音/无批注、G3 写入-回读逐条相等、G4 `%K`/`%P` 与日文逐行同构、G5 行首控制标记一致、G6 `NameTable.txt` 显示列不含假名**且不含 `●` 占位残留**、G7 正文不含 `●`（民汉表里被表内地址/序号污染出来的条目）、G8 **中文行自身 `「`/`」` 不配对而该行日文配对**。零日文回退约束也在这一层（覆盖不足直接 RuntimeError）。G8 与 `balance_brackets` 成对：修平步骤解决"能自动判断怎么修"的行，门禁拦住此后任何一层重新引入的不配对。

### 3.5 复检

**硬约束**：凡需要"重算某槽位应当是什么文本"的复检，一律调用 `tool/textfix.emit(jp, raw, fixed)`——与构建器同一个入口，不允许在调用方自己拼 `normalize()` 之后再补步骤。违反这条的表现为 `readback mismatch N` 且 N 恰等于新增出包步的命中行数。

一次性复检脚本（`acceptance*`／`built_defects`／`count_parity`／`fullwidth_scan`／`gb2312_scan`／`name_form_scan`／`nohan_scan`／`gloss_paren`／`three_way`／`slot_ctx` 等）的检查结论**已落入产物与改动表**，不再单独维护；日常复跑只需 `script/corpus/build_fan_translations.py` 出包 + 读产物核对。

## 4. 官方与民间的用词分歧（裁决记录）

民间表译自**日文底稿**，官方 zh-CN 是**英文底稿**的独立译本，两者对同一日文词常取不同译法。原则：只统一"会造成同一人同一物两种写法"的硬伤，不整体改写民间表的译风。取证按**文本配对**（不能按 idx——官方 idx 与原版错位）。

**按官方口径统一**（产物内部本身同时存在两种写法，属缺陷）：

| 民间旧写 | 统一为 | 依据 |
| --- | --- | --- |
| `亜纱` | `亚纱` | 官方全用 `亚纱`；产物内自身也以 `亚纱` 为多数 |
| `水瀬` | `水濑` | 官方全用 `水濑` |
| `风戸` | `风户` | 官方全用 `风户` |
| `恵风` | `惠风` | 官方全用 `惠风`（校名） |
| `蛍` | `萤` | 官方全用 `萤` |
| `寮母` | `管理员` | 官方"女生宿舍的管理员"；民间把日文汉字直接抄进中文 |
| 裸 `寮` | `宿舍` | 同上（`オンボロ寮→破旧宿舍` 词条在前，不受影响） |
| `部室` | `活动室` | 官方"社团活动室" |
| `｢｣` | `「」` | 官方全程只用 `「」`，半角钩括是日文排版残留 |

**保留民间写法**（忠于日文原文，改了会失真）：

| 民间 | 官方 | 日文原文 | 不改的理由 |
| --- | --- | --- | --- |
| `滑翔部` | `滑翔机社` | ソアリング部 | 日文就是"部"，官方把社团性质意译成"社" |
| `会长` | `社长` | 部長 | 学校社团语境下中文习惯称"会长/部长" |
| `部员` | `社员` | 部員 | 与"滑翔部"配套，改了会与前后文矛盾 |
| `机库`／`车库` | — | ガレージ | 民间自身混用，属语境层议题 |
| `円` | — | 円 | 日文货币单位在中文里通用，且是语料多数写法 |

**括注改写行的取词记录**（仅 `pin_glossp` 内实际用词，**不是**全表统一口径——同一假名词在其它行的不同写法一律保留原样）：`れろ`→舔舔、`ちゅ`→啾/啾噗、`じゅる`→啾噜、`ずるずる`→吸溜、`ぎゅっ`→紧紧抱住（其它行把 `ぎゅ` 写作「啾」的保持原样）、`むぎゅ`→咕叽、`もぐもぐ`→嚼嚼、`はぐはぐ`→啊呜啊呜、`ごくり`→咕咚、`ビクンッ`→猛地一颤、`ぽいっ`→唰、`チラッ`→瞟了一眼、`びゅっ`→噗/噗滋、`どくどく`→咚咚、`ぐすっ`→呜、`ほっ`→呼、`ッ――`→嘶、`ぜーっ`→呼哧、`くんくん`→嗅嗅、`ビシィ`→猛地一指、`あっかんべー`→略略略、`じぃ`→盯 等。

**破折号不做全局归一**：语料混用 `――`（U+2015×2）与 `——`（U+2014×2），机械层只做**逐行随日文**（日文 `――` 则中文 `――`），不做全表替换。

## 5. 产物清单与验收基线
